# pdf转 设置说明

> 配置文件就是纯文本的"设置.txt"。下面是逐项解释；每一节末尾都有一份可直接复制的完整示例。
> 依据：`why_harness\config.py`、`llm\client.py`、`pipeline\s1_pages.py`、`s2_layout.py`、`s3_ocr.py`、`s6_summary.py`、`cli.py`。查不到的标"（待确认）"。
> 本文不含任何凭证内容。

## 开头：本程序不绑定服务商

本程序不绑定任何服务商，也不内置任何 API 地址或模型名。它只要求你提供一个 **OpenAI 兼容的 `/chat/completions` 端点**（主流云厂商、代理、本地推理服务基本都提供这个接口）：在 `[提供商] 地址` 填端点 base URL，在 `[阶段.识别] / [阶段.摘要] 模型` 填模型名，凭证放进环境变量。

两个填写示例：

```
# 云端（示例，换成你自己的）
[提供商]
地址 = https://api.example.com/v1
key_环境变量 = WHY_API_KEY

# 本地（Ollama / vLLM / LM Studio 等；以你的实际端口为准）
[提供商]
地址 = http://127.0.0.1:8000/v1
key_环境变量 = WHY_API_KEY
```

- 地址以 `/v1` 结尾（结尾多余的 `/` 会被去掉），实际请求 `地址 + /chat/completions`。
- 模型名只发最后一个 `/` 之后的部分：写 `provider/model` 实际发 `model`。
- `地址` / `模型` 没填就调用会得到明确的中文提示（"未配置接口地址"/"未配置模型"），不会莫名报 KeyError 或网络错误。

## 0. 文件从哪来、怎么被读

- 默认模板：`why_harness\设置.txt`（包内）。
- `run` 的选取顺序：`--配置 <文件>`（给了就只用它）→ `<工作区>\设置.txt` → 包内模板。若最终用的是包内模板、而工作区没有 `设置.txt`，会把模板复制一份到工作区。
- 语法：
  - `[节名]` 一行；`键 = 值` 一行；`=` 两侧空格无所谓。
  - 只有整行以 `#` 或 `;` 开头才算注释；**行内注释和引号都不解析**（值会原样带上）。
  - 节名必须与代码里完全一致；代码里没有的键会被忽略（不报错）。
  - 文件必须能用 UTF-8 解码，否则 `run` 读配置时失败（"依赖或配置错误：…"，退出 3）。建议存 UTF-8 无 BOM（带 BOM 时第一行节名可能被跳过）（待确认）。
  - 键写在任何 `[节]` 之前会拼成 `.键`，代码取不到。

## 1. [提供商]

| 键 | 默认值 | 取值范围 | 改了会怎样 |
|---|---|---|---|
| `地址` | 模板里留空；代码里没有内置默认（取不到就是空串） | OpenAI 兼容的 `/v1` 地址；结尾多余的 `/` 会被去掉 | 决定请求发到哪：实际请求 `地址 + /chat/completions`。留空 → 调用时报"未配置接口地址：[提供商] 地址"；错值 → 网络/HTTP 错误，阶段失败（退出 2） |
| `key_环境变量` | 模板示例 `WHY_API_KEY`（代码兜底默认 `WHY_API_KEY`，只在配置里完全没有这一项时用） | 任意环境变量名 | 决定从哪个环境变量读凭证。改错 → 提示"未配置 key：请设置环境变量 <名字>" |

另有 `[提供商] key` 这个兜底项（可直接把凭证写进配置），不建议使用，本文不示例。

`自检 --连通` 读的是同样的 `地址` / `key_环境变量`（`key` 兜底也认）：向 `{地址}/models` 发 GET，超时 5 秒；连通打印"接口：正常"退出 0，失败或没配 key 退出 3。

可直接复制：

```
[提供商]
地址 = https://api.example.com/v1
key_环境变量 = WHY_API_KEY
```

## 2. [全局]

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `并发` | 4（模板与代码都是 4） | ≥1 的整数；写不成数字时回退 4 | **只影响 ⑥ 摘要**：同一层的节点并发调用，层与层串行（叶子层先跑）。调大 → 更快，但更容易触发服务端限流（429）；调小 → 更慢。① ② ③ ④ ⑤ ⑦ ⑧ 都是逐页/逐节点顺序处理，不受它影响。命令行 `run --并发 N` 覆盖本项（不给就用本项；`N < 1` 按输入错误退出 1） |
| `超时秒` | 180 | 正数（可小数）；代码按浮点解析，解析不了就回退 180 | **单次 HTTP 请求**的超时，不是整个阶段的预算。调小 → 大页/慢模型更容易超时并进入重试；调大 → 卡住时等更久。0 或负数没有校验，行为未定义（待确认） |
| `重试次数` | 2 | ≥0 的整数（负数按 0） | 一个请求内部的额外重试次数，总尝试次数 = 重试次数 + 1。只对网络错误、429、5xx、响应解析失败重试；400/401/402/403/404 直接失败 |
| `自动补跑轮数` | 2 | 0–10 | ③ 识别有页失败时，只把失败页放回池子自动再跑几轮；0 = 关闭。还失败就停下，之后可用 `补跑` 只补失败页 |
| `重试退避秒` | 1.0（**模板里没有这一项**，代码默认 1.0） | 正数 | 退避基数：第 1/2/3/4 次重试前等 0/8/25/60 秒 × 本值；429 若带 `Retry-After` 优先用它 |

可直接复制：

```
[全局]
并发 = 4
超时秒 = 180
重试次数 = 2
重试退避秒 = 1.0
```

## 3. [阶段.识别]（③ OCR）

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `模型` | 模板里留空 | 你方服务支持的模型名 | 请求时**只发最后一个 `/` 后面的部分**（`provider/model` → 实际发 `model`）。留空 → 调用时报"未配置模型：[阶段.识别] 模型"；写错 → 404"模型名不存在"，阶段失败（退出 2） |
| `文本层` | 模板 `自动` | `自动` / `总是识别`（写其它值等同 `自动`） | `自动`：① 判定该页有文本层（去空白后 > 20 字）就用本地取字重建段落，不花钱；`总是识别`：所有页都发图片给模型（更准，也更贵；扫描页本来就走模型） |

补充事实：文本层重建时，"字号 ≥ 全页正文中位字号 × 1.35、整行 ≤ 40 字、不占满排版宽、末尾不是标点"的行会被当标题，写作 `##`。

可直接复制：

```
[阶段.识别]
模型 =
文本层 = 自动
```

## 4. [阶段.摘要]（⑥）

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `模型` | 模板里留空 | 同上 | 只用于 ⑥；同样只发最后一个 `/` 之后的名字；留空 → 调用时报"未配置模型：[阶段.摘要] 模型" |
| `摘要最大字数` | 150 | 正整数 | 提示词里的 `{{limit}}`；模型返回的 summary 超过它会被**硬截断**（不报错）。改小 → 摘要更短；改大 → 更细更长，也更可能撞上模型输出上限 |
| `一句话最大字数` | 30 | 正整数 | 提示词里的 `{{brief_limit}}`。模型给的 brief 长度不超过本值 × 1.5 就采用（`by=model`），否则回退成"摘要首句截断到本值"（`by=heuristic`） |
| `正文上限` | 6000 | 正整数 | 送进模型 `{{body}}` 的字符数上限（超出截断）。叶子的 body 是 raw；中间节点是"【导语】+ 各子节点摘要"。改大 → 更全更贵；改小 → 丢信息 |

注意事项：

- `摘要最大字数` / `一句话最大字数` / `正文上限` 必须是能转成整数的值，否则 ⑥ 直接失败（退出 2）；`并发` 写错则回退 4。
- ⑥ 的缓存键 = 内容哈希 + **提示词文件哈希 + 模型名 + 摘要最大字数 + 一句话最大字数**。所以改提示词/模型/这两个上限会让旧缓存失效、重跑真的重做摘要；**改"正文上限"不会**让缓存失效（缓存键里没有它）；要强制重做用 `run --force`（⑥ 忽略缓存，按新的 `正文上限` 重调模型）或删 `状态\摘要\<书>.json`。
- 不做摘要（`status=skipped`）：role 为 `toc`/`index` 的节点；正文（中间节点是拼好的输入）去空白后不足 20 字的节点。
- 关键词：模型给的词必须是该节点 raw 的连续子串且 2–12 字，不合格的丢弃；全丢则 `status=keywords-dropped`。

可直接复制：

```
[阶段.摘要]
模型 =
摘要最大字数 = 150
一句话最大字数 = 30
正文上限 = 6000
```

## 5. [渲染]

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `倍率` | 2.0 | 正数（可小数）；解析不了就回退 2.0 | ① 渲染页图的分辨率倍数（`Matrix(倍率, 倍率)`）。调大 → 页图更大、② 检测更慢、③ 视觉识别更清楚；调小 → 更快更模糊，小字可能认不出 |

可直接复制：

```
[渲染]
倍率 = 2.0
```

## 6. [版面]

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `档位` | `M`（模板里也写了） | `M` / `plus-L` | ② 用哪个版面模型：`M` 快、标题类框少；`plus-L` 准、约 5–8 倍慢。图形界面「设置 → 质量与速度」可直接切；`run --档位` 可临时覆盖。`run` 开始时检查该档是否已安装，没装 → `模型缺失：<档位>`，退出 3。注意 `模型 download` 不带档位参数也会退出 3 |

另有 `设备`（模板里也写了）：跑版面模型的设备，`自动`（默认）/ `cpu` / `gpu:0`。
`自动` 只在 paddle 是 GPU 版且真的检测到 CUDA 显卡时才用 `gpu:0`；Intel/AMD 集显（HD/UHD/核显）不被 paddlepaddle 支持，选 `自动` 就是 CPU，程序会打印一行"使用 CPU"。显式写 `gpu:0` 而初始化失败时会自动回落 CPU，不会中断流水线。

可直接复制：

```
[版面]
档位 = plus-L
设备 = 自动
```

## 7. [输出]

| 键 | 默认 | 取值范围 | 作用 |
|---|---|---|---|
| `格式` | `both` | `both` / `md` / `why` | 交付什么：`both` = Markdown + .why（默认）；`md` = 只要 Markdown（.why 只当中间包放 `状态\包\`，不落到成品目录，也不导图片）；`why` = 只要单文件 .why（不导 Markdown 和图片，仍写一份 `说明.txt`）。命令行 `--输出` 可临时覆盖 |
| `保留中间数据` | `true` | `true` / `false` | 整本成功后是否保留 `状态\`（含页图）和 `日志\`。`false` = 只留成品，省空间，但之后不能再 `补跑`；失败或带缺口时**不删**，方便补跑 |
| `溯源段` | `true` | `true` / `false` | 是否在 .why 末尾写 TRAILER 溯源段（页数、文本层页数、版面模型与档位、识别方式统计、提示词指纹、摘要模型）。`false` 文件小一点，但事后查不到这些事实 |

可直接复制：

```
[输出]
格式 = both
保留中间数据 = true
溯源段 = true
```

## 8. 代码能读、模板里没写的键

| 节 | 键 | 默认 | 作用 |
|---|---|---|---|
| `阶段.识别` / `阶段.摘要` | `推理强度` | 空（不发该字段） | 非空时原样放进请求体的 `reasoning_effort`。注意：服务端不支持这个字段会返回 400，而 4xx 不重试（交接文档记过"部分服务端的模型不接受思考档位"） |
| `阶段.识别` / `阶段.摘要` | `单页最大token`（或 `token上限`） | 不发 | 非空时作为 `token上限参数名` 指定的字段发出去 |
| `阶段.识别` / `阶段.摘要` | `token上限参数名` | `max_tokens` | 换用别的字段名（例如某些服务用 `max_completion_tokens`） |

可直接复制：

```
[阶段.摘要]
推理强度 =
单页最大token = 2000
token上限参数名 = max_completion_tokens
```

（`推理强度 =` 留空 = 不发这个字段。）

## 10. 常改三件的速查

| 想干什么 | 改哪里 | 副作用 |
|---|---|---|
| 更快 | `[全局] 并发` 调大、`[版面] 档位 = M`、`[渲染] 倍率` 调小 | 并发大可能 429；M 档标题框少；倍率小可能认不清小字 |
| 更准 | `[版面] 档位 = plus-L`、`[渲染] 倍率` 调大、`[阶段.识别] 文本层 = 总是识别` | 明显更慢；`总是识别` 会让文本页也花钱 |
| 省 token | `[阶段.摘要] 正文上限` 调小、`摘要最大字数` 调小 | 摘要丢信息；`正文上限` 改了不会让旧缓存失效，需删 `状态\摘要\<书>.json` 或用 `run --force` 才会重做 |
