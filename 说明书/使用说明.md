# pdf转 使用说明

> 给"拿到程序的人"：装什么、模型放哪、完整命令怎么跑、工作区里每个文件是什么、出错怎么办。
> 事实以当前代码 `why_harness\`（开发目录 `D:\新版本`）为准。查不到依据的地方标"（待确认）"，没有编造。
> 本文不含任何凭证内容。

## 快速开始

第一次运行前先把 `[提供商] 地址` 和两个模型（`[阶段.识别] 模型`、`[阶段.摘要] 模型`）填上——就在工作区的 `设置.txt`（不写 `--工作区` 时是 `产物\<书>\设置.txt`，首次运行会自动复制模板；改哪个文件、本机绝对路径以程序提示为准）。没填就开跑会在进阶段之前退出 1，并直接告诉你缺哪一项、该编辑哪个文件。

## 双击启动（图形界面）

不用记命令：双击仓库根目录的 `启动.bat` 即可打开窗口。左栏是 **转换 / 提示词 / 设置 / 关于**，顶部右上角也有「设置」按钮；第一次用先点「设置」填接口和模型。

- 首次双击前，用记事本打开 `启动.bat`，把 `PY` 那一行改成你自己的 `pythonw.exe` 完整路径（要用 pythonw，不弹黑窗口；虚拟环境就写 `.venv\Scripts\pythonw.exe`）。
- **设置窗口**分四页：模型服务（可存多套、获取可用模型、测试连接）、质量与速度（快速档 M / 精确档 plus-L、思考强度、单次重试、自动补跑轮数、超时）、输出（工作区/扫描目录、交付格式、是否保留中间数据、.why 溯源段）、高级（路径与恢复默认）。
- 地址会自动补 `https://`、去掉结尾的 `/chat/completions`；key 会自动去掉 `Bearer ` 前缀。保存前会检查地址/key/模型名，缺了不让保存，省得跑到 ③ 才报错。
- 转换页可以直接把 PDF 或文件夹拖进窗口；运行栏能切「质量档」。失败时进度条会变红并在弹窗里说明原因（不会先跳到 100% 再报错）；关掉弹窗后点「补跑」只重试失败页和后续阶段。
- 也可以用命令 `python -m why_harness gui` 起窗口（不带参数）。
- 退出码在窗口状态栏显示：0 完成 / 1 输入有误 / 2 阶段失败 / 3 依赖或模型缺失 / 4 有缺口。

## 1. 装什么

### 1.1 Python

- 需要 Python 3.12。本机：`D:\Python312\python.exe`；虚拟环境 `.venv` 记录版本 3.12.10，home 指向 `D:\Python312`。
- 命令都在 `D:\新版本` 目录下执行（`python -m why_harness` 需要当前目录能 import 到 why_harness 包）。

### 1.2 两套依赖：用途不一样，别装混

| 解释器 | 现状（本机实测） | 能做什么 | 不能做什么 |
|---|---|---|---|
| `D:\Python312\python.exe`（全局） | 有 pymupdf（fitz）、Pillow；**没有** paddleocr / paddlepaddle | 模型管理（`模型 list/verify/download/remove`，只用标准库）；跑测试；跑不含版面检测的链路（② 会降级，插图/表格框为空） | 版面检测（② 需要 paddle） |
| `D:\新版本\.venv\Scripts\python.exe` | 上述之外还有 paddleocr 3.7.0、paddlepaddle 3.0.0、paddlex 3.7.2、numpy 2.3.5 等 | 完整八阶段（含 ② 版面检测） | — |

- 基础依赖（两套都要，口径见施工单）：pymupdf、Pillow。

```powershell
D:\Python312\python.exe -m pip install pymupdf pillow
```

- 版面依赖（只装给需要 ② 的那个解释器；版本按 `requirements-layout.txt` 固定）：

```powershell
D:\新版本\.venv\Scripts\python.exe -m pip install -r D:\新版本\requirements-layout.txt
```

`requirements-layout.txt` 内容：paddlepaddle==3.0.0、paddleocr==3.7.0、paddlex==3.7.2、pymupdf==1.28.2、pillow==13.0.0、numpy==2.3.5；文件头两行把 pip 源换成华为云 PyPI 镜像（`--index-url https://mirrors.huaweicloud.com/repository/pypi/simple` + 官方 PyPI 兜底），所以上面的 `-r` 命令不用再手动加 `-i`。

- 自查当前解释器有没有 paddle：`python -c "import paddleocr"` 不报错即可。
- 用全局解释器跑 `run` 时，② 会打印"版面模型未安装……缺少 paddleocr/paddlepaddle"，然后继续跑完，只是产物里没有插图。

## 2. 模型怎么放

### 2.1 两档

| 档位 | 模型名 | 官方包大小 | 本机解包后 | 官方注（代码里） | 实测（交接文档） |
|---|---|---|---|---|---|
| `M`（默认） | PP-DocLayout-M | 23,767,040 B（≈23.8 MB） | 3 个文件合计 ≈22.7 MiB | 快速档：CPU 约 1 秒/页；标题类框比精确档少 | 加载 10–29 s，单页 1.5–17 s |
| `plus-L` | PP-DocLayout_plus-L | 130,396,160 B（≈130.4 MB） | ≈124.4 MiB | 精确档：20 类版面检测，CPU 约 16 秒/页 | 加载 32–37 s，单页 28–45 s |

### 2.2 放在哪

放在**程序目录**下的 `模型\<档位>\`，必须正好这三个文件（名字不能改）：

```
模型\                              ← 程序目录下
  M\        inference.json   inference.pdiparams   inference.yml
  plus-L\   inference.json   inference.pdiparams   inference.yml
```

- "程序目录"：打包后 = exe 所在目录；开发时 = 仓库根（本机 `D:\新版本`）。开发者可用环境变量 `WHY_HARNESS_DIR` 覆盖程序目录、`WHY_MODELS_DIR` 直接覆盖模型根目录。
- 判定标准：三个文件都在且非空，就算"已安装"（不校验内容）。

### 2.3 怎么装（三选一）

```powershell
python -m why_harness 模型 list          # 列两档、是否已安装、模型目录
python -m why_harness 模型 download M     # 下载并安装 M 档
python -m why_harness 模型 verify M       # 只校验文件是否齐全
python -m why_harness 模型 remove M       # 删除该档
```

1. 命令行下载（上面四条；等价于 `python -m why_harness.media.models download M`）。
2. 手动：官网 tar 解包后，把 `inference.json / inference.pdiparams / inference.yml` 放进 `模型\<档位>\`。
3. 下载失败时程序会打印 tar 地址和最终目录，照提示放即可。

下载器行为：先给候选下载源（hf-mirror 国内镜像、官方 bcebos；`WHY_MODEL_MIRROR` 可指定自建镜像目录）各抓 512 KB 测速，选最快的下 → Range 续传到 `<档位>.part` → 校验 sha256 → 解包（防路径穿越）→ 逐文件原子改名；某个源失败或 sha256 不符会自动换下一个源重下。华为云镜像站没有托管 PaddleX 权重（任何路径都回一张网页），所以只用作 pip 源：`requirements*.txt` 里已把 `--index-url` 指向华为云 PyPI 镜像，缺的版本自动回落官方 PyPI。

### 2.4 换档位

默认 `M`，不改配置就是它。要用 `plus-L`，除了装好模型，还要在设置文件里加一节：

```
[版面]
档位 = plus-L
```

- `run` **一开始**就检查"设置里的档位是否已安装"，没装直接打印 `模型缺失：<档位>` 并以退出码 3 结束——即使这本 PDF 全是文本层也一样。所以至少要装一个档。

## 3. 一条完整命令

```powershell
cd D:\新版本
$env:PYTHONIOENCODING="utf-8"

# 凭证从环境变量读：变量名以设置文件 [提供商] key_环境变量 为准（模板示例 WHY_API_KEY，可改成你自己的变量名）
# 值由提供方给你，不要写进本文件或公开的地方
$env:WHY_API_KEY = "<你的值>"

# 不写 --工作区 时：工作区自动 = 产物\<书名>（这里是 产物\作文摘抄）；同一本书重跑复用同一目录（断点续跑）
D:\新版本\.venv\Scripts\python.exe -m why_harness run "D:\新版本\why-harness（发行版）\作文摘抄.pdf"
```

| 位置/参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `<pdf>` | 是 | — | 输入文件：PDF（完整八阶段），或 **Markdown/文本**（`.md` / `.markdown` / `.txt`，跳过 ②版面检测和 ③视觉模型，直接拿正文建书）；书名 = 文件名去后缀；文件不存在时打印"文件不存在"并退出 1 |
| `--工作区` | 否 | 自动：`产物\<书名>`（书名 = 输入文件名去后缀；相对当前目录） | 成品和中间数据都放这里。不写时每本书各自一个目录（互不混状态），同一本书重跑复用同一目录（断点续跑）；显式传了就原样用 |
| `--配置` | 否 | 见 §4 | 指定设置文件；不给时按 `<工作区>\设置.txt` → 包内模板 `why_harness\设置.txt` 的顺序取，并且工作区没有 `设置.txt` 时会把模板复制进去 |
| `--force` | 否 | 关闭 | 重做已有产物：传给签名里真有 force 形参的 ③（已存在且通过质量筛选的页稿也重做）和 ⑥（忽略摘要缓存、真的重调模型）；①②④⑤⑦⑧ 的 `run()` 没有 force 形参，收到 `--force` 行为不变 |
| `--并发` | 否 | 用设置文件 `[全局] 并发`（模板 4） | 给了就覆盖本次运行的 `[全局] 并发`，只影响 ⑥ 的节点并发（①②③④⑤⑦⑧ 顺序处理）；`< 1` 按输入错误退出 1 |
| `--档位` | 否 | 用设置文件 `[版面] 档位`（模板没有就是 M） | `M` = 快速档（约 1 秒/页，24 MB）；`plus-L` = 精确档（约慢 5–8 倍，130 MB）。覆盖后重新检查该档模型是否已装 |
| `--输出` | 否 | 用设置文件 `[输出] 格式`（模板 both） | `both` = Markdown + .why；`md` = 只要 Markdown（.why 只当中间包）；`why` = 只要单文件 .why（不导 Markdown/图片）。`补跑` 也认这个参数 |

运行时会打印 `开始 s1_pages` / `完成 s1_pages`，失败打印 `sN 失败：…`。最值得看的两个统计行：⑥（节点数、模型摘要、缓存命中、回退、跳过、调用次数）、⑦（节点、插图、表格、过期摘要、溯源段有无、字节数）。

其它子命令：

| 子命令 | 作用 | 备注 |
|---|---|---|
| `模型 list` / `模型 download <档位>` / `模型 verify <档位>` / `模型 remove <档位>` | 模型管理 | 缺档位参数 → 退出 3（未知档位） |
| `提示词 识别` / `提示词 摘要` | 打印 `prompts\ocr.md` / `prompts\summary.md` | 这两个文件由用户维护，程序只做变量替换；不带参数会按 argparse 惯例退出 2 |
| `自检` | 打印"工作目录：正常 / PATH：正常" | `--连通` 会用 `[提供商] 地址` + `key_环境变量` 发 `GET {地址}/models`（超时 5 秒）：通 → 打印"接口：正常"退出 0；失败打印原因退出 3；没配 key → 打印"未配置 key"退出 3 |
| `版本` | 打印版本串 | 当前打印 `pdf转 2.0.0` |
| `补跑 <pdf>` | 只补没做完的部分：①②④ 产物完整就整段跳过，③ 只重试失败页，然后接着跑 ⑤～⑧ | 不会问"复用还是重做"；已成功/已存在的页不重做，适合上次 ③ 有页失败或中途关掉之后用。支持 `--工作区 / --配置 / --并发 / --档位 / --输出` |
| `阶段 <1..8> <书>` | 只运行第 n 个阶段 | 按 `run` 同样的方式初始化工作区/配置并检查版面模型；①③ 的 `<书>` 要传 PDF 路径，其余阶段传书名（PDF 文件名去后缀）；支持 `--工作区 / --配置 / --force`；不写 `--工作区` 时默认 `产物\<书>`（①③ 取输入文件名去后缀，其余直接用书名）；退出码语义同 `run`（0/2/3/130） |

## 4. 工作区里每个目录/文件

默认 `程序目录\产物\<书>`（相对当前目录；`--工作区` 可换成任意目录）。`<书>` = 输入文件名去后缀。
不写 `--工作区` 时，每本书各自一个目录（`产物\作文摘抄`、`产物\另一本`…），互不混状态；同一本书重跑会复用同一目录，所以编号和摘要缓存能续上（断点续跑）。旧版的大目录叫 `运行时\`，第一次用新版时会自动改名成 `产物\`，旧稿不丢。

```
<工作区>\                    默认 程序目录\产物\<书>：成品和中间数据都在这一层
  设置.txt                 首次运行且未指定 --配置 时，自动复制的配置模板
  <书>.why                 最终电子书（.why 2.0 单文件）；[输出] 格式 = md 时不生成
  <书>.md                  从 .why 导出的 Markdown；[输出] 格式 = why 时不生成
  figures\img-<8位哈希><扩展名>   按内容去重后的插图（只在导出 Markdown 时生成）
  说明.txt                交付项/正文(只交付 .why 时是"电子书")/节点数/最深层数/图片行(有图才写)/表格数/过期摘要数
  状态\                    各阶段中间态（JSON + 图片）；[输出] 保留中间数据 = false 时成功后整个删掉
    页图\<书>.json          页数、每页宽高、文本层判定(text_chars/has_text_layer)、页图相对路径、PDF 书签
                            （Markdown/文本输入时 source_kind=text、page_png=null，每页的 md 正文放在 text 字段）
    页图\<书>\<书>-NNN-page.png
    版面\<书>.json          每页 boxes(label/score/bbox/kind)、figures/tables(key/bbox/path)、失败页 failures
    裁图\<书>\p{页}-f{序号}.png   插图裁图（外扩 6 像素）
    裁图\<书>\p{页}-t{序号}.png   表格区裁图
    页稿\<书>\<书>-NNN.md  每页识别结果（文本层重建或模型转写）
    ocr-<书>.json           ok/failed/calls/tokens + methods（每页是 text-layer 还是 vision）
    表格-<书>.json          页稿里 <table> 的解析结果（cells/html）
    章节-<书>.json          2.0 的树：节点、raw、page_map、守恒审计 conservation、编号复用 registry、warnings
    编号-<书>.json          编号登记表（重跑沿用编号用）
    摘要-<书>.json          每节点 summary/brief/keywords + 统计 + token
    摘要\<书>.json          摘要缓存（按内容寻址，重跑命中就 0 次调用）
    包\<书>.why            只交付 Markdown 时，.why 只当中间包放这里，不是成品
  日志\运行-YYYYMMDD-HHMMSS.jsonl  事件流：run_start、stage_end(耗时)、call(用量)、error、run_end；有缺口时多一条 gaps
  日志\阶段-<n>-YYYYMMDD-HHMMSS.jsonl  阶段 子命令的日志（同一套事件流）
```

- 交付什么由 `[输出] 格式` 决定（命令行 `--输出` 可临时覆盖）：`md` = 只要 Markdown（成品目录只有 `<书>.md`、`figures\`、`说明.txt`）；`why` = 只要单文件 `.why`（只多一份 `说明.txt`，不导图片）；`both`（默认）= 两样都有。
- 中间数据：`[输出] 保留中间数据 = false` 时，整本成功后才删 `状态\` 和 `日志\`（失败或带缺口不删，因为「补跑」还要用）。
- 溯源段：`[输出] 溯源段 = false` 时 .why 末尾不写 TRAILER（页数、版面模型与档位、识别方式统计、提示词指纹、摘要模型）；默认写。
- 工作区可以随便换；同一本书在同一工作区重跑时，编号和摘要缓存会尽量复用。
- 中间态 JSON 的具体字段见《why2.0格式规范.md》第 8 节和《接口约定.md》。

## 5. 退出码

| 码 | 含义 | 什么时候出现 |
|---|---|---|
| 0 | 成功 | 八个阶段全部完成 |
| 1 | 输入错误 | PDF 不存在；`--并发` < 1；没给子命令或子命令没匹配上 |
| 2 | 阶段失败 | 任一阶段抛异常（② 有页 detect 失败、③ 有页失败、⑤ 守恒越界、⑦ 写前自检不过、缺 pymupdf 等） |
| 3 | 依赖/配置/模型缺失 | 读配置或 import 出错（"依赖或配置错误：…"）；`run` 开始检查到 `模型缺失：<档位>`；② 版面引擎拿不到 / 模型加载失败（版面是必需阶段，会停下，不会产出没有插图的书）；`模型` 子命令自身异常 |
| 130 | 用户中断 | 按了 Ctrl+C |
| 4 | 有缺口（仍算跑完） | 八个阶段都跑完、日志仍记成功，但 ⑦ 打包的 `stale_summaries > 0`（有摘要与当前章节内容不匹配），或 ⑧ 交付的 `missing_refs` 非空（正文引用的插图在 .why 里找不到）。产物已生成，可检查后重跑 ⑥⑦⑧ |

## 6. 常见报错怎么处理

| # | 现象 | 原因 | 处理 |
|---|---|---|---|
| 1 | 控制台乱码，或 `UnicodeEncodeError: 'gbk' codec` | 控制台代码页不是 UTF-8 | 产品侧 `cli.py` 已把 stdout/stderr 切到 UTF-8；脚本或外部调用仍要 `$env:PYTHONIOENCODING="utf-8"` |
| 2 | `模型缺失：M`，退出 3 | 该档目录缺文件 | `python -m why_harness 模型 download M`，或按 §2.2 手动放三个文件 |
| 3 | ② 打印"版面模型加载失败（M，约 24 MB）"或"版面引擎不可用" | 当前解释器没装 paddle，或版面引擎导入失败 | 换 `.venv\Scripts\python.exe`，或按 §1.2 装版面依赖。版面是必需阶段：加载失败会停下并退出 3，**不再继续跑出没有插图的书** |
| 4 | `Model name mismatch`，或 M 档被当成精确档 | 加载版面模型时只给了 `model_dir`，没给 `model_name` | 程序内部已显式传 `PP-DocLayout-M` / `PP-DocLayout_plus-L`；自己改代码只传 `model_dir` 就会踩到 |
| 5 | Paddle 报中文路径相关错误 | Paddle 原生接口不认中文路径 | 程序内部用 `subst Y:` 映射 ASCII 盘符，失败就把三个权重复制到 `%TEMP%` 下的纯 ASCII 目录；用户不用处理，也别在别处再复制这套逻辑 |
| 6 | 阶段 1 失败：`No module named 'pymupdf'`，退出 2 | 该解释器没装基础依赖 | 按 §1.2 第 1 条安装 |
| 7 | `未配置 key：请设置环境变量 <名字>（[提供商] key_环境变量）` | 环境变量没设，或名字与 `[提供商] key_环境变量` 不一致（提示里的名字来自配置，不再是写死的） | 设好环境变量；只在真要调模型时才检查（⑥ 全命中缓存、③ 全文本层时不需要） |
| 8 | `key 无效或无权限` / `余额不足：请充值或换 key` / `模型名不存在` / `请求参数错误：…` | HTTP 400/401/402/403/404 | 4xx 一律不重试，阶段直接失败（退出 2）；按提示改 key、充值或改模型名 |
| 9 | `模型请求失败（HTTP 429/5xx）` / `网络请求失败：…` | 限流、服务端错误、断网 | 会重试 `重试次数` 次，退避 0/8/25/60 秒 × `重试退避秒`（429 优先用响应头 `Retry-After`）；用完才失败 |
| 10 | `输出被 token 上限截断` | 响应 `finish_reason=length` | 调大 `[阶段.X] 单页最大token`，或让提示词输出更短 |
| 11 | `内容被拦截或返回为空` | 响应 choices 为空 | 换模型或改提示词后重跑 |
| 12 | `插图 … 找不到裁图，也没有整页图可退回`，退出 2 | 版面缺该页图，整页图也不在 | 重跑 ①、②；或检查 `状态\裁图` 与 `状态\页图` |
| 13 | ⑤ 报守恒越界（"疑似合成内容"），退出 2 | 页稿字数与节点正文字数对不上 | 看 `章节-<书>.json` 的 `conservation` 与 `warnings`，重跑 ③ ⑤ |
| 14 | PowerShell 里 `... | Select-Object -Last 20` 之后退出码是 1 | 管道 EPIPE 造成的假退出码 | 不是程序失败；以程序实际打印和产物为准 |
| 15 | 反复重跑 | ① 页图会重渲染；③ 已存在且通过质量筛选的页稿会**跳过**；⑥ 命中缓存 0 次调用；⑤ 沿用旧编号 | 失败后先试 `补跑 <pdf>`：①②④ 完整就跳过，③ 只补失败页；要整本重做才用 `run --force`（③ 重做页稿、⑥ 忽略摘要缓存）；只想重跑某一阶段用 `阶段 <n> <书>` |
| 16 | 版面检测慢，想用显卡 | 见 `[版面] 设备` | 只有 NVIDIA 独显 + GPU 版 paddle 才能用 `gpu:0`；Intel/AMD 集显 paddlepaddle 不支持，程序会打印"使用 CPU"。集显上想加速只能换 OpenVINO/ONNX 路线，不属于现版本能力 |
